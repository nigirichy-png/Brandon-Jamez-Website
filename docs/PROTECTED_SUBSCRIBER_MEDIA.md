# Protected subscriber media

## Security boundary

Subscriber images and small videos live in the private Supabase Storage bucket `subscriber-media`. Object paths are generated by the server and bound to a post UUID and one of the allowlisted kinds `cover`, `content`, or `video`. The database stores only this stable private object path. It never stores a signed URL.

Subscriber list/detail RPCs expose only content fields and `has_*` availability flags; they never return the bucket name, an object path, or a signed URL. Subscriber pages expose only a same-origin path such as `/subscriber/media/post-slug/video`. On every GET or HEAD request, that Route Handler:

1. validates the slug, media kind, query string, and optional single byte range;
2. validates the current Supabase session;
3. rejects blocked accounts and missing or expired paid entitlement;
4. fetches the safe published-post DTO through an authenticated RPC that repeats paid-entitlement enforcement in PostgreSQL;
5. resolves the stored path through a separate server-only, `service_role`-only RPC and verifies that it belongs to the authorized post and media kind;
6. creates a 60-second Storage signed URL on the server;
7. fetches that URL internally and proxies only an allowlisted media response.

Admin draft preview uses a separate `preview=admin` branch. It requires a real, active, unblocked administrator both in application code and in the admin listing RPC. Only after that check may the server-only lookup include a draft. Development preview parameters never authorize the media route.

All gateway responses use `Cache-Control: private, no-store, max-age=0, must-revalidate`, reject content-type mismatches, and avoid logging object or signed URLs. Subscriber and subscriber-CMS routes also receive no-store and noindex headers from Next.js configuration. A canceled-at-period-end subscription retains access only while its trusted Stripe status remains active and its paid period is still in the future; ended, inactive, malformed, anonymous, and blocked states fail closed.

## Supported media

- Private images: JPEG, PNG, WebP, GIF, or AVIF, maximum 10 MB.
- Private video: MP4 or WebM, maximum 10 MB.
- Upload validation checks declared MIME type, size, basic file signatures, generated path shape, and post ownership.
- Video requests support a single HTTP byte range for normal browser seeking.

The 10 MB limit is deliberate. This same-origin proxy is suitable for images and short clips, not a large streaming library: the application runtime carries the response bandwidth, Supabase provides no adaptive transcoding here, and this is not DRM. For long-form or high-traffic video, use a reviewed private streaming provider with signed playback tokens, adaptive bitrate delivery, webhook validation, and the same repeated entitlement checks.

Large subscriber VOD is prepared separately through Bunny Stream in `docs/BUNNY_STREAM.md`. It does not replace this bucket or route. Bunny source uploads and HLS segments bypass the application runtime; subscriber DTOs expose only an availability flag and the playback route repeats entitlement checks before issuing a short-lived path-scoped CDN token.

## External-media boundary

YouTube and Vimeo embeds, direct HTTPS video URLs, and external image URLs are external media. They may reveal requests to their provider, may be shareable independently, and are not made private by embedding them on a protected page. The CMS and subscriber presentation label this boundary explicitly. Private Storage media is preferred when actual access control is required.

## Rollout checklist

1. Review and test migrations 007-010 in order in a disposable or controlled Supabase environment.
2. Confirm the bucket is non-public and browser roles cannot list or read its objects.
3. Regenerate database types from the deployed schema.
4. Test anonymous, inactive, expired, blocked, canceled-at-period-end, active-subscriber, and active-admin requests.
5. Test missing, traversal, cross-post, wrong-kind, wrong-MIME, malformed-range, and deleted-object cases.
6. Inspect rendered HTML and logs to confirm no Supabase signed URL or service credential appears.
7. Verify GET, HEAD, seeking, expiration, no-store headers, and entitlement revocation in the deployed runtime.
